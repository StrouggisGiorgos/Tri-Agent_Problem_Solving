# Tri-Agent_Problem_Solving
The original workflow developed for Chapter 4 of the thesis: LLMs for Tabular Data.

![Tri-Agent Workflow](image-url)

**Tri-Agent Problem Solving** is the name we decided to give to our prompting technique. As the name suggests, it utilizes three separate agents each to perform their own tasks:

* **Thinker**: The first agent is given the name 'Thinker' and the role of a seasoned data scientist to put it in a 'scientific mindset'. It is then presented with the general context of what it must do regardless of which specific step of the process we are on: it must read the given task and devise a plan to approach it using natural language and without writing or executing code. Afterwards it is given a basic idea of the dataset schema such as our column names to maintain internal consistency and knowledge of relevant items. Finally, it is given what its task actually is. The purpose of the Thinker is to mimic the Chain-Of-Thought technique and provide a carefully thought out idea for how one would go about performing any step, without actually performing it. By taking things slower and focusing more on the logic of a task, we prevent the model from making rash decisions. To further guarantee that the Thinker will not perform its own idea, it is not given the data, only the aforementioned schema.
* **Performer**: The second agent's purpose is to use the Thinker's idea and act it out, effectively performing the second half of the Chain-Of-Thought technique: the actual actions after the idea has already been conceptualized by the Thinker. The model is given the name 'Performer' and its role as an expert python programmer before it is told that its task is to read through our data and follow the Thinker's method in order to derive the desired results while preserving all the relevant information. To perform all of the above, the Performer is given our data, the output given by the Thinker as well as the raw step that was also given to the Thinker for further context.
* **Evaluator**: The third agent's purpose as the seasoned data scientist 'Evaluator' is to examine the output of the Performer against the baseline data and see if it accurately followed instructions to provide the correct result. To do this, it must carefully iterate through all the data and mark down the accuracy of each and every result so that only when it determines that every single output was correct would it deem the Performer's actions as correct. Should it do so, then it will inform us of a successful verdict and allow to proceed into the next step, otherwise it will write out an explanation for why the Performer's output was inaccurate. The Evaluator is given the baseline data and the output of the Performer in order to cross-examine them, as well as the current step being undertaken to provide the context for this evaluation.

Tri-Agent Problem Solving implements Least-To-Most Prompting by breaking down our task into each individual step and sending them in a for loop one at a time to the Thinker. Once it has developed its method for an individual step, the Thinker's output is passed onto the Performer who performs the filtering and whose output is then passed onto the Evaluator. The Performer and Evaluator are located inside a while loop that prevents them from advancing into the next step unless the Evaluator assesses that the Performer's output was correct, at which point it takes the place of the baseline data for the next step. Otherwise, it will explain what mistakes the Performer made and the while loop will repeat, only this time the Evaluator's verdict is added to the Performer's input to correct its mistake in the next iteration of the while loop.

Dataset used is the Smartphone Addiction dataset found in [Kaggle](https://www.kaggle.com/datasets/jayjoshi37/smartphone-usage-and-addiction-prediction)
